    ## AI 요약

    ## 갤럭시 워치 홈 앱 성능 분석 플랫폼 개발 개요

삼성전자 MX사업부에서 개발한 **갤럭시 워치 홈 앱 성능 분석 플랫폼**은 에러 로그가 남지 않는 간헐적 화면 버벅임(**Jank**) 원인을 파악하고 코드 개선안을 도출하기 위해 개발되었습니다. 규칙 기반 자동 재현, **Perfetto SQL** 전처리, 로컬 소스코드 매칭, 그리고 6종의 **AI 어드바이저**를 결합한 하이브리드 구조를 통해 분석 리드타임을 1주일에서 30분으로 단축했습니다.

---

## 주요 개발 배경 및 한계점

갤럭시 워치 홈 앱은 단일 프로세스 내에 홈, 알림, 타일, 앱스 등 대형 모듈이 공존하며, 기존 안드로이드 분석 툴이 거의 동작하지 않는 환경입니다. 
- **수동 분석의 한계:** 수백 MB 규모의 **Perfetto 트레이스(`.pftrace`)** 파일을 수천 개 프레임과 일일이 대조해야 해 이슈 1건당 평균 1주일이 소요되었습니다.
- **구조적 제약:** 단일 프로세스 내 모듈 간 경합, 시스템 프로세스와의 CPU 경쟁, 수동 재현의 편차, 그리고 경량 **LLM** 사용 시 발생하는 토큰 한도와 **할루시네이션** 문제가 존재했습니다.

---

## 하이브리드 파이프라인 아키텍처 (3단계 워크플로)

플랫폼은 결정론적 처리가 필요한 영역은 규칙 기반 코드로, 복합 맥락 추론은 **AI**로 역할을 분리하여 설계되었습니다.

### 1단계: 규칙 기반 시나리오 자동 테스트 (Stage 1)
- **AI**를 배제하고 **ADB** 기반 스크립트를 사용하여 단말 초기 상태를 고정합니다.
- 동일한 좌표, 속도, 타이밍의 입력을 가해 **Perfetto 트레이스**와 화면 녹화를 동기화 수집합니다.

### 2단계: 하이브리드 AI 자동 분석 파이프라인 (Stage 2 ~ 5)
- **SQL 전처리 및 소스 매칭 (Stage 2):** **Perfetto SQL**을 교차 질의해 노이즈 없는 정형 JSON 근거 패킷을 생성하고, 로컬 소스코드를 정적 매칭합니다.
- **동적 역할 선택 (Stage 3):** 트레이스 병목 특성에 맞춰 전문 어드바이저 조합과 실행 계획을 수립합니다.
- **6종 도메인 전문 어드바이저 (Stage 4):** UI 드로우, 메인 스레드, 렌더 스레드, CPU 스케줄러, I/O 대기, 소스코드/트레이스 태그 영역을 분업화하여 시차 병렬 추론을 수행합니다. 
- **종합 분석 및 검증 게이트 (Stage 5):** **Claim Gate**와 **Final Gate**의 2단계 로컬 검증을 통해 **할루시네이션**과 시스템 지연의 앱 오귀속을 차단합니다.

### 3단계: 대화형 Q&A 기반 코드 개선안 도출 (Stage 6)
- 리포트 생성 직후 개발자가 곧바로 조치할 수 있도록 전용 대화형 **Q&A** 창이 활성화됩니다.
- 검증된 컨텍스트를 바탕으로 1·2순위 코드 개선안 및 추천 **트레이스 태그**를 즉시 제시합니다.

```json
{
  "analysis_target": "Galaxy Watch Home App",
  "lead_time_reduction": "1 week -> 30 minutes",
  "jank_frame_improvement": "47.68% decrease"
}
```

## 최종 성과 및 교훈

본 플랫폼 도입을 통해 주요 시나리오의 **Janky Frame**을 **47.68% 감소**시켰으며, 주요 액티비티 실행 시간을 **20.31% 단축**했습니다. 개발 과정에서 얻은 핵심 교훈은 다음과 같습니다.

1. **사전 지식의 중요성:** **LLM**이 내부 소스코드를 모르면 **할루시네이션**이 발생하므로 로컬 소스코드 후보와 도메인 구조를 먼저 제공해야 합니다.
2. **정제된 데이터:** 저성능 **LLM** 환경에서는 **SQL 전처리**를 통해 노이즈를 걷어내고 핵심 지표만 전달하는 것이 성능을 좌우합니다.
3. **규칙과 AI의 시너지:** 재현·집계·검증은 규칙 기반으로, 복합 원인 추론은 **AI**로 결합할 때 강력한 자동화가 가능합니다.
