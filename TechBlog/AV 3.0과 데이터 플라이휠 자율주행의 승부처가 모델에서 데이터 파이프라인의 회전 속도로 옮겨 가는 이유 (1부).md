    # AV 3.0과 데이터 플라이휠: 자율주행의 새로운 승부처

## 1. AV 3.0의 패러다임 변화와 롱테일 문제
자율주행 기술은 단순한 모델 성능 경쟁을 넘어, **자사 데이터로 얼마나 빠르게 재학습·검증하느냐**의 경쟁인 **데이터 플라이휠** 구조로 전환되고 있습니다.
- **AV 3.0의 특징**: 인지·예측·계획을 통합한 엔드투엔드(2.0) 방식을 넘어, 판단 근거를 설명하는 추론(Reasoning) 기능이 더해진 **VLA(Vision-Language-Action) 모델**이 주를 이룹니다.
- **롱테일 문제**: 실제 도로에서 드물게 발생하는 위험한 돌발 상황(낙하물, 경찰 수신호 등)을 실제 주행만으로 확보하기 어려우므로, **합성 데이터**와 **폐루프 시뮬레이션**을 통한 보완이 필수적입니다.

## 2. NVIDIA의 Cloud-to-Car 전략과 오픈 모델
NVIDIA는 자율주행 개발을 위해 세 가지 컴퓨터(학습용 **NVIDIA DGX**, 시뮬레이션용 **NVIDIA Omniverse 및 Cosmos**, 차량용 **DRIVE AGX**)를 연동하는 클라우드-투-카 파이프라인을 제시합니다.
- **주요 오픈 모델**: 주행 판단을 위한 **Alpamayo** 계열 모델과 데이터 생성·증강을 위한 월드 모델 **Cosmos**를 제공합니다.
- **최적화 기법**: 대형 교사 모델의 지식을 소형 모델에 이전하는 **증류(Distillation)**와 숫자 정밀도를 낮추는 **양자화(Quantization)**를 통해 차량 내 실행 제약을 극복합니다.

## 3. AWS 기반의 8단계 데이터 파이프라인 아키텍처
AWS와 NVIDIA가 공동 제시한 참조 아키텍처는 수집부터 검증까지 8단계의 파이프라인을 AWS의 관리형 서비스로 구현합니다.

```
[데이터 수집] -> [품질 검증] -> [큐레이션] -> [검색·색인] -> [선택·증강] -> [장면 재구성] -> [모델 학습] -> [SiL 검증]
```

- **수집 및 저장**: `Amazon S3`와 `AWS DataSync`를 활용해 대용량 주행 로그를 안전하게 저장하고 관리합니다.
- **처리 및 학습**: `Amazon SageMaker HyperPod`와 `AWS Batch`를 통해 대규모 클러스터 연산 및 병렬 처리를 수행하며, Blackwell 기반 인스턴스(`G7e`, `P6-B300`)를 활용합니다.
- **검색 및 오케스트레이션**: `Amazon OpenSearch Service`의 벡터 검색으로 필요한 학습 장면을 빠르게 추출하며, `Amazon SageMaker Pipelines`로 전체 파이프라인을 관리합니다.

## 4. 시사점
완성차 업체(OEM)들은 자체 주행 스택과 NVIDIA 기반 프로그램을 병행하는 **투 트랙(Two-Track) 전략**을 취하더라도, 공통된 데이터 파이프라인과 표준화된 검증 체계를 구축하는 것이 개발 속도를 좌우하는 핵심 승부처입니다.
