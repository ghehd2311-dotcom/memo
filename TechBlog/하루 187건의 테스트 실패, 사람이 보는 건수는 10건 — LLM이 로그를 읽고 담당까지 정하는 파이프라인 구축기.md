    ## AI 요약

    ## TV 소프트웨어 테스트 실패 로그 자동화 분석 파이프라인 요약

### 1. 배경 및 문제점
* **자동 테스트의 한계**: 수백 대의 TV 장비에서 자동 테스트가 수행되면서 **하루 평균 180건 안팎의 실패 로그**가 발생.
* **분석의 병목**: 수천 줄에 달하는 로그와 장비 시리얼 로그, 소스 코드를 사람이 직접 확인해야 하므로 **건당 평균 30분** 소요.
* **목표**: 사람이 직접 로그를 열어보지 않고도 정확한 원인을 파악할 수 있는 자동화 파이프라인 구축.

---

### 2. 주요 해결 방법 및 파이프라인 구조

#### 분석 지식 자동 생성
* **동작 마커 사전 및 실행 흐름**: LLM이 코드 본문을 읽고 `JSON` 형태로 마커(설명, 부작용 등)를 생성하며, 실행 흐름을 문서화하여 '왜' 이 동작이 실행되었는지 파악.
* **CI 연동**: 코드가 변경될 때마다 지식을 자동으로 재생성하도록 **CI 빌드**에 강제하여 지식의 노후화 방지.

#### 효율적인 LLM 로그 분석 (Grep 우선 분석)
* **토큰 절약**: 대용량 로그(수백만 토큰)를 통째로 입력하지 않고, **`grep`**을 활용해 최종 실패 지점 전후 최대 50줄만 부분적으로 읽어 분석 시간 및 비용 단축.
* **코드 블록 예시 (로그 분석 및 마커 구조)**:
```json
"clean_usb": {
  "desc": "USB 경로 하위 전체를 삭제한 뒤 목록을 확인한다.",
  "phases": ["finalize"],
  "side_effects": ["DELETE/FORMAT"],
  "example_commands": ["rm -rf /usb/*"]
}
```

#### 실패 건 선별 및 대표 분석
* **코드 기반 분류**: LLM 없이 코드로 에러 메시지 패턴을 묶고, 급증/신규/재발 유형을 판별하여 하루 분석 예산(96건) 내에서 15분마다 대표 실패 건을 분석.
* **일일 리포트 및 Jira 연동**: 집계 및 숫자는 코드가 처리하고, LLM은 요약에만 활용하여 솔루션 담당용 **Jira 이슈 자동 등록** 및 재발 감지 기능 구현.

---

### 3. 도입 성과 및 핵심 원칙

#### 주요 성과 지표
* **원인 파악 시간**: 평균 **30분**에서 AI 분석 **4.3분(중앙값)**으로 단축.
* **사람이 받는 건수**: 하루 약 180건에서 **할 일 10건 안팎, 새 이슈 1건 안팎**으로 대폭 감소.
* **생산성**: 사람의 요청 없이 누적 **1,333건**의 분석 리포트 자동 생성 (신규 유형의 88% 당일 포착).

#### 정립한 3가지 원칙
1. **지식은 코드에서 생성**: 사람이 직접 관리하는 사례집 대신 **코드 기반 자동 생성 및 CI 강제** 활용.
2. **LLM의 역할 제한**: 묶기, 집계, 우선순위 등은 코드로 처리하고 **LLM은 로그 해석과 리포트 요약에만 사용**.
3. **근거 강제**: 리포트에 없는 원인 추측 금지 및 **근거 ID 명시**로 결과물 신뢰도 향상.
