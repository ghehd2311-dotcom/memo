
    # AI의 답에 동료 AI가 질문을 던졌다― weave-agents로 엮은 멀티 벤더 AI 협업

    링크:
    https://techblog.samsung.com/blog/article/107

    ## AI 요약

    ## weave-agents 개요와 개발 배경

**weave-agents**는 서로 다른 벤더의 AI(Codex, Claude, Gemini, Cline 등)에 구현과 검토 역할을 나누어 맡기고, 의견이 충돌할 경우 코드와 테스트를 통해 검증하는 협업 스킬 및 하네스 시스템입니다. 

기존의 사내외 협업 아이디어(Code Review War, JEV의 행동 선택, 역할 분담 등)를 하나의 흐름으로 엮어, 모델의 남은 사용량과 자체 평가 기록을 종합적으로 고려하여 최적의 담당을 배정합니다.

---

## 주요 기능 및 작동 방식

- **하네스(Harness) 중심 조율:** 사용자와 대화 중인 AI가 하네스를 맡아 목표와 범위를 설정하고, 적절한 AI 담당을 배정한 뒤 결과를 검토합니다.
- **다양한 검토 프로세스:** 
  - **추가 검토:** 초기 검증을 통과한 코드라도 검사 범위의 빈틈(예: JavaScript 파일 누락)을 찾아 보완합니다.
  - **반박 검토:** AI의 잘못된 오류 지적(회귀 오류 등)을 실제 코드 및 테스트 결과와 대조하여 걸러냅니다.
- **담당 배정 기준:** 역할별 품질(60%), 남은 사용량(25%), 배정 기회(15%)의 비중을 계산하여 특정 모델에 작업이 편중되는 것을 방지합니다.

---

## 코드 및 검사 범위 개선 사례

실제 인증 처리 코드 검토 과정에서 검사 대상 확장 및 오류 처리 검증이 이루어졌습니다.

```typescript
// 수정 전: TypeScript 파일만 검사
/\.tsx?$/.test(entry.name)

// 수정 후: JavaScript 파일(.js, .jsx)까지 검사 범위 확대
/\.[tj]sx?$/.test(entry.name)
```

- **인증 범위 보완:** 요청 목적지 확인, 대소문자 구분 처리 정비, 검사 대상 파일 확장자 확장을 통해 숨겨진 빈틈을 메웠습니다.
- **오류 지적 필터링:** 잘못된 회귀 지적은 기각하고, 유효한 보안 위험 지적은 유지하며, 정책 결정이 필요한 사항은 사용자에게 판단을 요청했습니다.

---

## 활용 예시

**weave-agents**를 활용할 때는 다음과 같이 목표와 검토 범위를 지정하여 시작할 수 있습니다.

```bash
weave-agents로 이번 인증 변경을 구현하고 검토해 줘. 
구현과 독립 리뷰를 나누고, 요구사항과 실패 경로를 서로 다른 관점에서 봐 줘. 
의견이 다르면 근거를 확인해 정리해 줘. 이번에는 로컬 수정까지만 진행해 줘.
```

실제 업무 적용 결과, 판정을 마친 의견 173건 중 **129건 채택, 44건 기각**의 성과를 거두었으며, 앞으로도 역할별 선택 기준과 실행 안정성을 지속적으로 보완해 나갈 계획입니다.
