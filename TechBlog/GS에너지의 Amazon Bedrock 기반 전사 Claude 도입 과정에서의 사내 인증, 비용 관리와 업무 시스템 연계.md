    ## AI 요약

    ## GS에너지의 **Amazon Bedrock** 기반 전사 Claude 도입 요약

GS에너지는 임직원들이 안전하고 효율적으로 생성형 AI를 활용할 수 있도록 **Amazon Bedrock**과 **Claude**를 기반으로 한 전사 공통 AI 서비스인 **AI Hub**를 구축했습니다. 본 요약은 도입 배경, 아키텍처, 인증, 보안 및 운영 방식을 다룹니다.

---

## 1. 도입 배경 및 핵심 요구사항
부서별 개별 사용으로 인한 비용 통제 및 보안 취약점을 해결하기 위해 전사 공통 플랫폼 구축이 추진되었습니다. 주요 요구사항은 다음과 같습니다.
* **회사 계정 연동**: SSO(Okta) 로그인을 통한 인증 및 인사 변동에 따른 자격 갱신·회수
* **비용 및 예산 관리**: 팀 단위 예산 설정 및 사용량 추적
* **통합 정책 적용**: 단일 진입점과 게이트웨이를 통한 모델 및 콘텐츠 정책 관리
* **보안 네트워크**: 인터넷 경로가 없는 **VPC** 환경 구축 및 **AWS PrivateLink** 활용
* **권한 분리**: 모델 이용 권한과 업무 데이터 접근 권한의 분리

---

## 2. 솔루션 아키텍처 및 네트워크
AI Hub는 인터넷 게이트웨이가 없는 사설 VPC 환경에서 안전하게 운영됩니다.

```
[임직원 PC] -> (AWS Transit Gateway) -> [Internal ALB]
                                           ├──> [Lambda (VPC 밖): 인증/토큰 검증]
                                           ├──> [LiteLLM 게이트웨이 (ECS)] -> [Bedrock (VPC 엔드포인트)]
                                           └──> [MCP 커넥터 서버 (Lambda)] -> [사내/SaaS 시스템]
```

* **진입점**: 사내망에서 **AWS Transit Gateway**를 거쳐 **Internal ALB**로만 접근 가능
* **LLM 게이트웨이**: **Amazon ECS** 상의 **LiteLLM**을 통해 키 검증, 예산 관리, 사용 원장 기록 수행
* **보안 격리**: 외부 연동 및 인증 검증이 필요한 기능만 VPC 밖의 **AWS Lambda**로 분리하고 **IAM 권한**으로 통신

---

## 3. 인증 및 키 관리 구조 (Virtual Key)
사용자는 API 키나 AWS 설정을 직접 다루지 않으며, 시스템이 자동으로 키를 관리합니다.

* **발급 프로세스**: Okta 로그인 후 토큰 검증 ➔ 이용 자격(팀 매핑) 확인 ➔ **Virtual Key** 자동 발급 (운영체제 자격 증명 저장소 보관)
* **자동 회수**: Okta Event Hook을 통해 퇴사 및 계정 비활성화 시 즉시 키 삭제
* **조직 동기화**: 매일 새벽 인사 시스템의 조직 정보를 반영하여 팀 매핑 갱신

---

## 4. LLM 게이트웨이와 예산·콘텐츠 정책
* **예산 관리**: 팀 예산 소진율에 따라 알림(70%, 90%), 모델 하향 조정(90%), 요청 차단(100%) 단계별 대응
* **로그 분리**: 대화 본문이 없는 **Amazon DynamoDB**(사용 원장, 3년 보관)와 입출력 원문이 담긴 **Amazon S3**(KMS 암호화, 90일 보관)를 분리하여 운영
* **콘텐츠 정책**: **Amazon Bedrock Guardrails**를 연동하여 주제, 개인정보, 콘텐츠 필터링 적용

---

## 5. MCP 커넥터를 통한 업무 도구 연계
**Claude Desktop**의 **MCP(Model Context Protocol)**를 활용해 임직원 PC에 별도 프로그램 설치 없이 업무 시스템과 연동합니다.
* **인증 방식**: 전사 협업시스템은 **On-Behalf-Of(OBO)** 토큰 교환을 사용하여 사용자 본인의 권한 범위 내에서만 데이터 조회
* **쓰기 통제**: 쓰기 작업(메시지 전송 등)은 허용된 사용자만 가능하며, 미리보기와 실행 단계를 분리하고 감사 기록을 남김
* **Office 추가 기능**: Word, Excel, PowerPoint 등에서 조직 배포 형태의 추가 기능을 통해 동일한 게이트웨이 정책 적용

---

## 6. 결론 및 향후 계획
GS에너지는 **로그인, 모델 이용, 업무 데이터 접근 권한을 엄격히 분리**하고, 모든 호출이 통제되는 구조를 확립했습니다. 향후 계획은 다음과 같습니다.
* **SAP S/4HANA** 등 사내 기간 시스템 연동 확대
* **Amazon Bedrock** 내 **OpenAI 모델** 추가 연동
* 여러 모델과 MCP 커넥터를 조합하는 **GenAI 통합 포털** 구축
