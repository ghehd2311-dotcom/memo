    # TV 앱 실행 시간 측정 자동화 도구 개발 요약

## 1. 배경 및 해결 과제
* **기존 방식의 문제점**: TV 앱 실행 시간 측정은 실물 TV에 리모컨 신호를 보내고 화면을 지켜봐야 하므로 사람이 직접 수행해 왔습니다.
* **소요 시간 및 제약**: 부팅 후 정확히 3분을 대기해야 하며, 1회 측정에 약 5분이 소요되어 월 평균 32.5시간이 소요되었습니다. 또한 판독자별 편차와 결과 파편화 문제가 있었습니다.

---

## 2. 자동화 도구 목표 및 구성
PC, USB IR 송신기, 웹캠을 활용하여 **코드로 제어 가능한 모든 단계를 자동화**하였습니다.
* **IR 신호 송신**: 제조사 프로토콜별 raw 파형 전송 및 3분 대기 시간 포함
* **프레임 판독**: 웹캠 영상을 통한 목표 화면 자동 판정
* **결과 정리**: 증거 영상 녹화 및 사내 위키 자동 리포트 업로드

```bash
# 주요 사용 기술 스택 예시 (OpenCV 및 GUI 제어)
import cv2
from PySide6 import QtWidgets

# 결정적 영상 처리를 통한 프레임 판정 로직 (LLM 미사용)
def detect_app_launch(frame, roi):
    # OpenCV 기반 1ms 미만의 연산 처리
    processed = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)
    return is_target_screen(processed, roi)
```

## 3. 핵심 설계 원칙

### 3.1 결과 판정에 LLM을 쓰지 않은 이유
* **재현성 및 속도**: 매번 결과가 달라질 수 있는 LLM 대신 **OpenCV** 기반의 결정적 영상 처리 알고리즘을 적용하여 프레임당 1ms 미만의 처리 속도와 일관된 수치를 확보했습니다.
* **비용 및 보안**: 매달 수십만 장의 프레임 처리에 따른 토큰 비용 발생을 방지하고 보안 이슈를 차단했습니다.

### 3.2 다중 세션 개발에서의 맥락 유지 방법
대화창의 한계를 극복하기 위해 저장소 내 **Markdown 파일**로 맥락을 유지했습니다.
* **`CLAUDE.md`**: 전체 구조 및 설계 이유 기록
* **주제별 규칙 파일 7종**: 상태 머신, IR 송신 제약, 실패 이력 등 관리
* **`prompt_history.md`**: 사람의 요청 원문과 AI의 조치 내역 기록

## 4. 개발 성과
* **개발 기간 단축**: 혼자 진행 시 **약 52주** 소요될 공수를 **Claude Code**와 함께 **7주(실제 작업 16일)** 만에 완성했습니다.
* **업무 효율성 향상**: 측정자가 TV 앞을 지키는 시간이 **95% 감소** (월 32.5시간 $\rightarrow$ 약 1.6시간, 연간 약 371시간 절감).
* **핵심 원칙**: **"실물은 사람이 보고, 수치는 결정적 알고리즘이 내고, 맥락은 파일로 남긴다"**는 원칙을 확립했습니다.
